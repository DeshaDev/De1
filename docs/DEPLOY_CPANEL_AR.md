# نشر هَيَّا نَقْرَأْ على cPanel (تطبيق Node.js)

هذه الحزمة تشغّل **التطبيق كاملًا** (واجهة React وواجهات API الصوتية) عبر خادم Node.js. رفع مجلد `dist` وحده إلى `public_html` لا يكفي؛ لأن تسجيل الكلمات وتقييم Azure وحفظ التقارير تمر عبر `server.js`.

## 1) متطلبات الاستضافة

- تفعيل **Setup Node.js App** في cPanel مع Node.js 22.
- توفر مساحة تطبيق Node.js تعمل خلف Passenger.
- نطاق التطبيق مضبوط على `hayanaqra.com` (أو النطاق الفرعي المقصود).
- مجلد تخزين دائم وخاص خارج المسار العام للويب.

إذا كانت باقتك لا توفر تطبيق Node.js، فلن تكفي File Manager لتشغيل المنتج الكامل. لا تحوّل التطبيق إلى ملفات ثابتة؛ يلزم تشغيل خادم Node.js أو نشره على خدمة تدعم Node.js مثل Render.

## 2) إنشاء التطبيق لأول مرة

1. خذ نسخة احتياطية من مجلد الموقع الحالي وأي ملف إعدادات أو قاعدة بيانات.
2. افتح **cPanel → Setup Node.js App → Create Application**.
3. اختر Node.js 22 وProduction، واضبط Application Root على مجلد خاص مثل `hayanaqra-app`، واربط Application URL بالنطاق المطلوب.
4. اجعل Startup File هو `server.js`.
5. ارفع ملف `hayanaqra-cpanel-deploy.zip` إلى Application Root ثم فك ضغطه داخله. يجب أن تكون `server.js` و`package.json` في جذر Application Root، ومجلد `dist` بجانبهما.
6. من واجهة التطبيق في cPanel شغّل **Run NPM Install**. إذا لم يتوفر الزر، افتح Terminal داخل Application Root ونفّذ:
   `npm install --omit=dev --legacy-peer-deps --no-audit --no-fund`
7. أضف متغيرات البيئة الموضحة أدناه، ثم اضغط Restart.

**لا تستبدل ملف `.htaccess` الذي ينشئه cPanel لتطبيق Node.js.** لا ترفع ملفات الحزمة إلى `public_html` باعتبارها موقعًا ثابتًا.

## 3) متغيرات البيئة

أدخل الأسرار في واجهة Setup Node.js App، وليس داخل ZIP أو ملفات يمكن تنزيلها من الويب:

- `NODE_ENV=production`
- `BASEERA_SESSION_SECRET`: سر مستقل عشوائي لا يقل عن 32 حرفًا.
- `BASEERA_TENANT_CREDENTIALS`: كائن JSON، مع رموز دخول مستقلة عالية العشوائية لكل دور/مدرسة.
- `BASEERA_STORE_ENCRYPTION_KEY`: مفتاح مستقل بطول 64 خانة سداسية عشرية.
- `BASEERA_DATA_DIR`: مسار مجلد دائم خاص وقابل للكتابة، مثل مسار خارج `public_html`.
- `TRUST_PROXY_HOPS`: اتركه 0 ما لم يحدد مستضيفك عدد الوكلاء الموثوقين بدقة.
- `AZURE_SPEECH_KEY` و`AZURE_SPEECH_REGION`: مطلوبان لتقييم الصوت.
- `SUPABASE_URL` و`SUPABASE_ANON_KEY` و`SUPABASE_SERVICE_ROLE_KEY`: حسب إعدادات مشروع Supabase. لا تضع Service Role Key في متغير يبدأ بـ `VITE_`.
- `GEMINI_API_KEY`: اختياري لوظائف Gemini.

لا تنسخ أسرار التطوير أو الاختبار إلى الإنتاج، ولا تضع أي أسرار داخل المستودع أو ملف ZIP.

## 4) تحديث إصدار قائم

1. خذ نسخة احتياطية من `server.js` ومجلد `dist` وملفات الإعدادات والبيانات الدائمة.
2. ارفع ZIP الجديد إلى **Application Root نفسه** وفك الضغط مع استبدال ملفات الإصدار: `server.js` و`dist` وملفات package.
3. احتفظ بملفات cPanel الخاصة مثل `.htaccess`، وبمجلد البيانات الدائمة، وأي ملفات إعداد محلية خارج الحزمة.
4. شغّل **Run NPM Install** إذا تغيّرت التبعيات، ثم Restart من cPanel.
5. افتح الموقع في نافذة خاصة أو نفّذ Hard Refresh بـ Ctrl+Shift+R.

## 5) التحقق بعد النشر

في شاشة «قارئ الكلمات» يجب أن ترى كلمة واحدة فقط، وزر **«ابدأ تسجيل هذه الكلمة»**. بعد إرسال تسجيلها وتلقي رد تقييم الكلمة ينتقل العرض إلى الكلمة التالية. يجب ألا تظهر شبكة الكلمات الـ16.

اختبر أولًا بملف اصطناعي وبموافقة اختبار مناسبة، وتحقق من أن طلب كل كلمة يحتوي معرّف بند واحدًا فقط، وأن التقرير لا يُنشأ قبل اكتمال جميع الكلمات. لا تستخدم تسجيلات أطفال حقيقية في اختبار النشر.

إذا بقيت شبكة الكلمات بعد التحديث، افحص أن النطاق يشير إلى تطبيق Node.js الذي حدثته، وأن Application Root يحتوي ملف `server.js` ومجلد `dist` الجديدين، ثم افحص إعدادات CDN/Cache. نجاح بناء GitHub لا يعني أن هذه الملفات وصلت تلقائيًا إلى cPanel.

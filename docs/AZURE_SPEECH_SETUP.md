# إعداد Microsoft Azure Speech في بصيرة

هذا المسار يقيّم **التسجيل الصوتي الفعلي**؛ لا يكتفي بالنص الذي يلتقطه Chrome. مفاتيح Azure تبقى على الخادم ولا تُرسل إلى المتصفح.

## 1. إنشاء مورد Speech

1. أنشئ مورداً من نوع **Speech** في اشتراك Azure الخاص بك.
2. افتح **Keys and Endpoint** وانسخ إحدى المفاتيح واسم المنطقة (Region) كما يظهران في بوابة Azure.
3. في ملف `.env` المحلي، املأ:
   - `AZURE_SPEECH_KEY` بمفتاح المورد.
   - `AZURE_SPEECH_REGION` بالمنطقة نفسها التي ينتمي إليها المفتاح.
4. لا تستخدم بادئة `VITE_` لهذه القيم، ولا ترفع ملف `.env` إلى GitHub.

يمكنك نسخ `.env.example` إلى `.env` ثم استبدال القيم التجريبية. لا تضع المفتاح في React أو أي ملف يرسل إلى المتصفح.

## 2. تثبيت الحزم وتشغيل المشروع

```bash
npm install
npm run dev
```

أعد تشغيل الخادم بعد تعديل `.env`. عند غياب المفتاح أو المنطقة، سيعرض الفحص رسالة صريحة بدلاً من إنشاء درجة وهمية.

## 3. إعداد جلسة القراءة

- يجب تأكيد موافقة ولي الأمر والموافقة المنفصلة على إرسال التسجيل لمعالجة النطق قبل بدء الجلسة.
- يرسل المتصفح التسجيل النهائي بصيغة WAV/PCM أحادي القناة، 16 كيلوهرتز.
- يدعم هذا المسار حالياً نموذج Azure للنطق المصري `ar-EG` والنموذج السعودي `ar-SA`. اللهجات الشامية والمغاربية لا تُمرر إلى أحد النموذجين بصمت.
- للتسجيل القصير الذي لا يتجاوز 28 ثانية والنص المرجعي الذي لا يتجاوز 100 حرف، يطلب النظام وسوم المقارنة بالنص المرجعي. للقراءة الأطول يستخدم التعرف المستمر؛ Azure لا يدعم `EnableMiscue` في الوضع المستمر، لذلك تبقى الكلمات غير المحسومة معلّمة بوضوح بدلاً من اعتبارها حذفاً مؤكداً.

## 4. ما الذي يعنيه التقرير؟

هذه نتيجة تقييم آلي وليست تشخيصاً لعسر القراءة. الكلمات التي لا يستطيع مزود الصوت حسمها لا تُصنّف أخطاء على الطفل، ولا تدخل في حساب WCPM أو دقة الكلمات حتى تُحسم. يلزم اختبار الأداء على تسجيلات عربية حقيقية مع نتائج مرجعية بشرية قبل استخدام الدرجات لاتخاذ قرارات تعليمية عالية الأثر.

# نشر نسخة تجريبية من بصيرة على Render

هذا المستودع يحتوي على `render.yaml` و`Dockerfile` لتهيئة خدمة ويب تعمل بخادم Node.js وقرص دائم لتخزين حالة المدرسة المشفّرة. **إضافة الإعدادات إلى GitHub لا تنشئ رابطًا عامًا تلقائيًا**؛ يجب إنشاء Blueprint داخل حساب Render ثم إدخال الأسرار المطلوبة.

## خطوات النشر

1. افتح [Render Blueprints](https://dashboard.render.com/blueprints) واختر إنشاء Blueprint جديد من مستودع `DeshaDev/De1`.
2. جهّز قيمة `BASEERA_TENANT_CREDENTIALS` بصيغة JSON. يجب إنشاء رمز مستقل لكل دور، من 48 حرفًا سداسيًا عشريًا صغيرًا. أنشئ كل رمز على حدة باستخدام `openssl rand -hex 24`. لا تضع رموزًا حقيقية في المستودع أو في ملف `.env.example`.
3. عند مطالبتك بقيمة `BASEERA_STORE_ENCRYPTION_KEY`، أدخل ناتج `openssl rand -hex 32` (64 خانة سداسية عشرية). ينشئ Render `BASEERA_SESSION_SECRET` تلقائيًا. لا تعِد استخدام أي مفتاح أو رمز وصول.
4. أكمل إنشاء الخدمة ثم انتظر نجاح النشر. سيظهر العنوان العام في لوحة Render؛ لم يتم إنشاء عنوان حي للمشروع قبل إتمام هذه الخطوة.
5. اختبر الصفحة الرئيسية وتسجيل الدخول بحسابي التجربة، ثم أنشئ سجلًا اصطناعيًا وتحقق من بقائه بعد إعادة تشغيل الخدمة. لا تستخدم بيانات أطفال حقيقية.

## ملاحظات ضرورية قبل عرض النسخة للجمهور

- يتطلب القرص الدائم خطة Render مدفوعة. راجع [مواصفات Render Blueprint](https://render.com/docs/blueprint-spec) و[وثائق الأقراص الدائمة](https://render.com/docs/disks).
- أُعدّ هذا الإعداد لاختبار تقني ببيانات اصطناعية، وليس دليلًا على الجاهزية القانونية أو الأمنية أو التربوية للإطلاق.
- لا تُدخل بيانات طلاب حقيقية قبل إكمال مراجعة الخصوصية، والموافقات، وصلاحيات الوصول، ومزودي الخدمات ومواقع معالجة البيانات.
- تعطيل النشر التلقائي مقصود حتى يمكن مراجعة تغييرات الكود قبل تحديث النسخة المستضافة.
